# 办公室聊天、表情，与刘正超改任领导 — 设计

日期：2026-09-30 · 状态：已确认，待实施

## 背景

办公室现在是一个能走动、能打人、能看见别人光点的空间，但**人和人之间说不上话**。PLAN.md 的 Bounds 一直写着「No chat」——本设计推翻这一条。

多人此刻几乎体现不出来：同 area 能看见彼此的精灵，跨 area 只有小地图上一个光点，除此之外零互动。聊天是补这个缺口最直接的一件事。

同时，刘正超的人设从「一位随机血量、会走动会玩手机的同事」改为**压榨下属、毫无能力也毫无管理经验的 NPC 领导**。这件事表面是换文案，实际落在同一轮里，因为他的点名台词要知道「此刻楼里有谁」，读的是和聊天同一份数据；他的气泡和玩家的气泡也是同一套渲染，挤在一起时的叠加规则必须一起定。

## 范围

**做**：玩家打字聊天 + 头顶气泡 + 小地图上的隔壁气泡；六个表情（数字键与斜杠命令双入口）；刘正超台词重写并支持点名。

**不做**（明确留到后续轮次）：房间成员名单、PvP、聊天记录面板、刘正超还手、打倒刘正超给积分。

## 六个已确认的决定

1. **一句话是事件，不是状态**：服务器 `broadcast('chat', …)` 一次，客户端自己维持过期表。刘正超的 `say` 一并迁到这条通道，`Enemy.say` 从快照中删除。
2. **全楼层广播**：同一个 Colyseus 房间（= 一家公司）的所有人都收得到，不分 area，不按距离。
3. **只要气泡，不做聊天记录面板**：说过就过去了。
4. **隔壁的话显示在小地图上**：不同 area 的发言，在其投影光点旁画截短的文字。
5. **表情双入口**：数字键 `1`–`6` 与斜杠命令读同一张表。
6. **刘正超全楼层随机点名**：点名对象从全房间在线玩家中随机挑。

## 架构

### 为什么是事件而不是状态

快照每 2 tick 全量广播一次（`server/world.ts:197`，15 Hz）。把一句话放进 `Actor.say`，意味着它在存活期间**每秒被重复发送 15 次**：一句 40 字中文约 120 字节，单个发言者 1.8 KB/s，24 人同时说话时每客户端 43 KB/s、服务器出口约 1 MB/s。

24 人还远不到瓶颈，所以这不是性能决策，是**语义决策**：状态该表达「他在哪、血剩多少」，事件该表达「刚刚发生了什么」。用状态表达事件，就必须靠每帧重发来维持它存在——那 15 倍放大正是分类错误的症状，而不是一个可以单独优化掉的开销。

仓库里已有先例：`hit`（`server/world.ts:155`）——伤害数字同样转瞬即逝，走的就是广播事件加客户端临时渲染。

代价：中途加入或重连的人看不到正在飘的那句话。对聊天这是**正确**行为——走进会议室不该看到三秒前的话还挂在别人头上。

### 消息通道

客户端 → 服务器，新增一条：

```ts
// 二选一，不同时给。emote 只传 id，文案由服务器查表。
type ChatMessage = { text: string } | { emote: EmoteId };
```

两条入口（数字键与斜杠命令）在服务器汇合进同一个 `onMessage('chat')` 处理器，所以净化、限流、查表、点名填充各只有一份实现。

服务器 → 全房间广播：

```ts
interface ChatEvent {
  id: string;        // 说话者的 actor id（玩家 sessionId 或 NPC.id）
  text: string;      // 已净化、已截断、表情已查表、点名已填名
  kind: 'say' | 'emote';
  ms: number;        // 气泡存活毫秒，由 bubbleMs() 算出
}
```

`kind` 只影响颜色：表情描述的是动作不是话语，用偏灰的字，这是 MUD 时代就定下的区分。

**事件里不带 area。** 气泡画在头顶还是画在小地图，按**快照里说话者当前的 area** 实时判断，每帧重算。把发言时的 area 冻进事件里会错：一句话活 3–9 秒，足够说话者穿过一道门；冻住的话，他人已经站在你面前，气泡还留在小地图上的隔壁房间——或者反过来。位置本来就要每帧从快照读（气泡得跟着精灵走），顺手读 area 不多花任何东西。

沿用现有规则：**`hp <= 0` 时气泡不显示**（`src/game.ts:222`）。躺平的刘正超不说话。

## 键盘归属

这是本轮风险最集中的地方。

底部 `stage-bottom`（`src/main.ts:27`）内加一个默认隐藏的 `<input>`。`Enter` 开、`Enter` 发、`Esc` 关。

### 交接的三处，漏一处就是可复现的 bug

现有的 `blocked()`（`src/main.ts:45`）只认 `dialog[open]`。聊天框不是 `<dialog>`，所以：

1. **`blocked()` 要同时认聊天框开着**，否则打字打到 `J` 就挥拳（`src/game.ts:158`）。
2. **`src/main.ts:162` 的 preventDefault 名单里有 `Space`**。聊天框获得焦点后这条若仍生效，**打不出空格**——症状是「键盘坏了一半」，和聊天看不出关系。
3. **关闭时必须 `resetKeys()`**（复用 `src/game.ts:93` 已有的调用）。按 `Enter` 开聊天那一刻你可能正按着 `D`；`removeCapture`（`src/game.ts:77`）意味着焦点在输入框时画布收不到 `keyup`，Phaser 那边 `D` 会一直是按下状态。关掉聊天，人就自己往右走，而你没碰任何键。

数字键 `1`–`6` 要加进 `addKeys` 与 `removeCapture` 两份名单（`src/game.ts:75-77`），并同受 `blocked` 管：**在聊天框里打「1」不能触发挥手**。

### 中文输入法

打「你好」时按 `Enter` 是在**确认候选词**，不是发送。不设防的话，每个用中文输入法的人第一次打字都会把半截拼音发出去——「nihao」直接飘在头顶。

`keydown` 处理器开头必须放行组字期间的按键：

```ts
if (event.isComposing || event.keyCode === 229) return;
```

`keyCode === 229` 是老 WebKit 不设 `isComposing` 时的兜底。这条写死在 `src/chat-input.ts` 并在 PLAN.md 记一笔——它属于「写下来时是对的、但没人记得为什么」的代码，不记就会被后人当冗余清理掉。

**无法用 node 测试覆盖**（需要真实输入法），只进浏览器 QA 清单。

### 什么时候才能聊天

不在开场的跳过监听器里给 `Enter` 开特例（那是两个监听器互相让路），改为一个派生判断：

```ts
const canChat = () => openingDone && !!network.profile;
```

`openingDone` 在 `openingSequence()` 的 `finally`（`src/main.ts:71`）里置一次。身份沿用全仓库统一的那句 `if (!network.profile) { show(authDialog); return; }`——**没工牌时按 Enter 弹工牌对话框**，与按 `J`、按 `E`、点商店的行为一致（`src/main.ts:75`、`src/main.ts:81`）。

## 气泡

### 时长按字数算

`bubbleMs(text)` 纯函数：`2500 + 150 × 字数`，夹在 3000–9000 毫秒。

定值 5 秒两头都不对：两个字的「（点了点头）」挂 5 秒像卡住，40 字的句子 5 秒读不完。中文阅读约每秒 5–8 字，斜率照此。

### 长度上限 40 字，服务器截断

截断必须按**码点**切：

```ts
[...text].slice(0, 40).join('')   // 不是 text.slice(0, 40)
```

`'👍'.length === 2`。用 `slice` 会从代理对中间切开，屏幕上是一个乱码方块。

气泡宽度限 240px 自动折行（Phaser Text 的 `wordWrap`），40 字正好三行。

### 叠加的两种情况

- **同一人连说两句**：新的顶掉旧的。表按 id 索引，天然就是这个行为，无需代码。
- **几个人站在一起**：气泡现在全是 `depth 10001`（`src/game.ts:210`），平的，谁盖谁随机。改为跟随人物深度，**前面的人的气泡盖住后面的人的**——与斜视渲染层已有的深度纪律一致。名牌与血条维持 10000 不动（它们小，重叠代价低）。

### 小地图上的隔壁气泡

`src/minimap.ts`（现 40 行）：对**当前 area 与我不同**的发言者，在其 `projectTo` 投影出的光点旁画截短文字（前 6 字 + `…`）。同 area 的人不画——他们的话已经在头顶了，画两遍是噪音。**跨 area 的气泡同时最多 2 条，取最新**，否则小地图被糊满。

**点名到本人的那句高亮成薄荷绿 `#a6e8c2`**（与「你」的名牌同色）。这是给「全楼层随机点名 + 隔壁只能看小地图」这个组合打的补丁：你在茶水间被会议室的领导点名，否则只能看见一个被截短的气泡，不知道那句是冲你来的。

## 限流与净化

**限流**照现有 `noticeAt` 写法（`server/world.ts:208`）：`p.chatAt`，间隔 1200 ms，超出**静默丢弃**。回一条「说太快了」反而给刷屏者一个可以刷的东西。客户端挡同样的间隔，服务器只是兜底。

**`sanitizeChat(raw)` 纯函数**（`shared/game.ts`），依次：

1. 去控制字符与换行（换行会把气泡撑成怪形状）
2. 折叠连续空白
3. trim
4. 按码点截断到 40
5. 空串返回 `undefined`（调用方据此丢弃，不广播空气泡）

### 注入：头顶气泡安全，小地图不安全

头顶气泡是 Phaser Text，画在 canvas 上，没有注入面。

**小地图不是。** `src/map-panel.ts:112` 用的是 `get('map-players').innerHTML = …minimapDots(…).map(dot).join('')`——SVG 字符串拼接。今天安全只是因为那里流过的全是数字和服务器生成的 id；**聊天文本会是第一个到达这个 `innerHTML` 的用户可控字符串**。而 `escape()` 目前私藏在 `src/main.ts:19`，`map-panel.ts` 根本没有引用它。

因此：抽出 `src/escape.ts`，`main.ts` 与 `map-panel.ts` 共用，小地图气泡文本与被点名的昵称都必须经过它。这一条要有测试钉住（断言 `<img onerror=…>` 出现在标记里时是转义过的），否则它会在某次重构里被悄悄去掉。

## 表情

`shared/game.ts` 加 `EMOTES` 表，六条，数字键与斜杠命令读同一张：

| 键 | id | 命令 | 气泡文字 |
|---|---|---|---|
| `1` | `wave` | `/挥手` | （挥了挥手） |
| `2` | `clap` | `/鼓掌` | （鼓了鼓掌） |
| `3` | `sigh` | `/叹气` | （叹了口气） |
| `4` | `nod` | `/点头` | （点了点头） |
| `5` | `shrug` | `/摊手` | （摊开双手） |
| `6` | `busy` | `/忙` | （疯狂敲键盘，假装很忙） |

- 客户端只发 `{ emote: 'wave' }`，**文案在服务器查表**。这不是防作弊（文本消息本来就能发任意字），是保证六句话全仓库一处定义——与 `ORG_NAME` 同一个规矩。
- **斜杠命令在服务器解析**，不在客户端拆，解析器因此只有一个。认不出的 `/xxx` 回一条 `notice`。
- 表情气泡用偏灰的字（`kind: 'emote'`）。

## 刘正超改任领导

人设：压榨下属、毫无能力也毫无管理经验的 NPC 领导。名牌从「刘正超」改为「刘正超 · 主管」。

`NPC_LINES` 重写为四类。前三类是他的本体，第四类是模板：

**甩锅**
- 我不干事情的，我就是个传话的。
- 这个我不会啊，你们谁懂谁来。
- 出了问题别找我，我当时就提过风险。

**画饼**
- 这些都在我脑子里，我理一理再跟你们说。
- 今年把这块做起来，明年就好办了。

**踢皮球**
- 大家想想怎么做啊，我听听。
- 这个得拉个群对齐一下。
- 你们先做吧，我下午还有事。
- 先按你的想法来，出了事我们再说。

**点名**（含 `{name}`）
- 这个 {name} 处理一下。
- {name} 你说说，这个怎么弄。
- {name} 辛苦一下，今天之内。
- {name} 你年轻，多担待点。

### 规则

- 抽到点名句时，从**全楼层在线玩家**中随机挑一个昵称填入。
- **一个玩家都没有时，整类跳过**，退回前三类。这不是新发明，是仓库里已有的同一个套路：走廊没有工位，`spotAtDesk(corridor)` 返回 `undefined`，抽到「回工位」就退化成「玩手机」，而不是把人塞进墙里假装那是工位（PLAN.md 已记）。同样地，没人可点就不点，而不是点一个叫 `undefined` 的同事。
- 昵称是 maxlength 12 的用户输入，填入后与其他文本一样走 `sanitizeChat()`（防昵称里夹带换行）。
- 他说话的**时机逻辑完全不动**（`sayAt` / `sayEveryMinMs` / `sayEveryMaxMs`），只换投递方式：服务器端的 `say` / `sayUntil` 两个字段删除，到点直接 broadcast。
- **本轮不动他的战斗行为**：仍不还手，打倒仍不给分。

### 分寸

台词全部锁在**无能、甩锅、踢皮球**上，不碰性别、地域、外貌。最重的一句是「你年轻，多担待点」——职场里听着确实刺耳，但它刺的是这套话术本身，而不是被点名的那个人。这是这类笑话唯一能成立的位置。点名对象是真实用户自己起的昵称，玩笑与冒犯之间就隔着这条线。
