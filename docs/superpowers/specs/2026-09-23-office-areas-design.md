# 办公室分区、转场与 3/4 斜视视角 — 设计

日期：2026-09-23 · 状态：已确认，待实施

## 背景

当前办公室是一张 1920×1200 的连续平面，六个房间只是这张平面上的矩形区域，24 名玩家共享同一个 Colyseus room，`roomAt()` 仅用于显示地名。相机是纯俯视的 RTS 相机（光标锚点滚轮缩放、鼠标边缘滚屏/拖拽平移），已经可用。

本设计把世界从"一张平面"改成"走廊 + 若干独立房间"，把纯俯视美术改成固定 3/4 斜视，并在最外层加一张全国地图。

## 范围变更 — 2026-09-23（在实施中途确认）

1. **方向键归还给人物**。WASD 与方向键**都**移动人物，办公室与副本一致。视角平移因此只保留鼠标手段：边缘滚屏、拖拽、小地图点击/拖拽。键盘不再平移视角。这推翻了本文档原先"方向键平移视角"的设计。
2. **只做 PC 端，不考虑移动端**。剩余任务不新增任何移动端代码路径，不做移动端 QA，验收清单中的移动端项目全部移除。既有的触屏方向键与双指缩放代码**保留不动**（删除是另一项改动，未被要求），但视为不受支持、不维护。

## 已确认的四个决定

1. **视角角度**：固定 3/4 斜视（牧场物语 / 星露谷那种），镜头角度**永不改变**。立体感来自美术（墙体和家具有高度），不来自相机。相机的缩放与平移行为保持现状。
2. **房间语义**：房间是**真正独立的 area**，有自己的坐标空间，内部可以比外观大。
3. **实施范围**：第一期开放**大会议室**和**储物间**两间；其余四间的门做成可见的封闭状态（「装修中」），踏上去回提示，不换 area。
4. **最外层**：登录后先看全国地图，点击杭州总部进入楼层。

## 架构

### 世界数据结构

`shared/office.ts`（现 82 行）拆分为：

```
shared/world/types.ts      Rect / Area / Exit / Furniture 类型
shared/world/corridor.ts   走廊平面（沿用现有 1920×1200 布局）
shared/world/meeting.ts    大会议室内部 1100×760
shared/world/storage.ts    储物间内部 1100×760
shared/world/index.ts      AREAS 注册表 + canStandAt / moveIn / exitAt / projectTo
```

```ts
export interface Area {
  id: AreaId;                      // 'corridor' | 'meeting' | 'storage'
  name: string;                    // 显示名：大会议室
  width: number; height: number;
  spawnPoints: { x: number; y: number }[];
  obstacles: Rect[];               // 墙 + 家具的地面足迹
  exits: Exit[];
}
export interface Exit {
  rect: Rect;                      // 触发器
  to: AreaId;
  at: { x: number; y: number };    // 目标 area 内的落点
  label: string;
  locked?: boolean;                // 「装修中」的门
}
```

`canStandAt(area, x, y)` 与 `moveIn(area, actor, input, dt)` 由"读模块全局"改为"收 area 参数"。现有的 substep 防穿墙逻辑不变。

### 走廊平面与房间的关系

走廊平面**视觉上零变化**：六个房间照旧画出内部的桌椅货架。区别只有两点：

- 踏过门口的行为，从"走进去"变成"触发转场"。
- 房间内部在碰撞数据上标记为不可达（防御性，防止未来加第二扇门或碰撞回归导致玩家卡进无出口的幽灵副本）。因为四面墙本来就是实心的、唯一开口是门，这个标记在当前布局下不会被触发。

房间里的玩家通过 `projectTo(area, x, y)` 归一化映射回走廊平面上该房间的矩形，在全景和小地图上渲染成人影点。因此**从楼层全景能一眼看到哪间屋子有人、谁在里面**。

### 服务端（方案 A：单 room 内分 area）

保持一个 `WorldRoom`，不为房间开新的 Colyseus room。理由：进门零延迟（下一 tick 生效，不等网络往返）；`allowReconnection`、`activeAccounts` 账号单例、房间处置逻辑全部不动；24 人上限仍属整层楼，不会碎成每房间各自的上限。

- `Player` 与 `Actor` 各加 `area: AreaId`。现有 snapshot 是手写广播而非 Colyseus schema 同步，加字段成本接近零。
- `step()` 中 `moveOffice(p, input)` → `moveIn(AREAS[p.area], p, input)`。
- 移动后检查 `exitAt(area, p.x, p.y)`：
  - `locked` 的出口 → 单发 `notice`（「办公室 1 还在装修中」），不换 area。
  - 否则换 `p.area`、坐标设为 `exit.at`、设置 `exitCooldown = 400ms`、单发 `transition { from, to, name }`。
- **反向弹跳防护（两道）**：`exit.at` 放在门内侧 60px 处，与目标 area 的出口触发器不重叠；`exitCooldown` 期间不检测出口。
- `snapshot` 下发**全部**玩家，每人带 area。投影坐标**不下发**——`projectTo` 在 shared 层，客户端自行计算，省带宽也消除一处不一致来源。

### 受影响的现有判定

| 位置 | 现在 | 改为 |
|---|---|---|
| 商店可用 | 坐标落在储物间矩形内 | `p.area === 'storage'` |
| 副本入口 | `x > 1620 && abs(y-600) < 65` | `p.area === 'corridor' && x > 1620 && …` |
| 复活坐标 | 写死 `x=160, y=WORLD.floor`（副本地面坐标，在办公室会把人扔进墙里，现存 bug） | 当前 area 的 spawn |
| 上线落点 | `OFFICE.spawn + players.size * 45`（会叠人） | 在**全部已开放 area（含走廊接待区）**的 `spawnPoints` 中随机取一个 area，再在该 area 的候选点里挑离他人最远的 |

### 客户端

出生范围包含走廊，是为了避免第一期只有两间开放房间时走廊长期空无一人。若希望严格"只出生在房间里"，把 `corridor` 的 `spawnPoints` 清空即可——一行数据改动，无需改代码。

**开场序列**（登录后一次性，约 3.5 秒，任意键/点击跳过）：

```
全国地图 ──点击杭州总部──→ 楼层全景（停 1.5s）──推镜+淡入──→ 随机出生的房间
```

三层结构在第一次上线时完整展示一遍，而不是做成每次都要多点一下的菜单。之后想看全景，滚轮滚出来即可。

**踏门转场**（约 600ms，纯客户端表演）：

```
服务端换好 area（瞬时） → transition 消息 → 黑场淡入 180ms
  → 换场景、重建可视角色、相机对准落点 → 淡出 220ms
```

**关键取舍：服务端不等转场动画。** 踏过门的那一刻服务端就认为你在会议室里了。好处是转场期间断线、或动画因切后台卡住时服务端状态始终确定；代价是动画期间你看不见但能被房间里的人看见约 180ms。办公室内不能互相攻击，无实际影响。

**权威规则（贯穿全局）**：`snapshot` 是权威，转场动画只是补间。任何时刻本地场景 area ≠ snapshot 中我的 area，**立刻硬切、不播动画**。这一条同时覆盖切后台导致 tween 挂起、转场中途断线重连、消息乱序三种情况。

**相机**：沿用现有 `OfficeCamera`。它目前在 `minZoom` 与 `apply()` 的夹取里硬读 `OFFICE.width / OFFICE.height`，需改成读当前 area 的尺寸——这是唯一的改动点，锚点缩放、平移、边缘滚屏等逻辑不动。`minZoom` 于是自然变成"当前 area 铺满舞台"。

**小地图**：在走廊显示整层楼（含房间内人影投影）；在房间内切换为该房间的平面图，顶部加「大会议室 · 返回走廊」按钮。点击是给人物一个寻路目标走到门口，**不是瞬移**，保持"位置由服务端决定"。

### 渲染层（3/4 斜视）

**斜视完全不碰碰撞和服务端。** 碰撞永远使用物体在地面上的投影足迹；斜视只在渲染时把顶面上抬 `height` 像素。世界坐标、`canStandAt`、`moveIn`、`step()` 一行不动。

每件物体画三层：地面投影（暗色，贴合足迹）→ 立面（顶面色压暗约 20%）→ 顶面（即现有那层）。高度写在 `shared/world` 的家具数据里。

**遮挡是本次改造的真正难点**：现在整层楼画进一个 `Phaser.Graphics`，共享一个深度。斜视下人物必须能被桌子遮挡。因此 `src/office-map.ts` 拆为：

```
src/render/oblique.ts         足迹+高度+配色 → 投影/立面/顶面，纯函数
src/render/area-renderer.ts   遍历 area 的墙与家具，每件一个 Container，setDepth(足迹底边 y)
```

角色 sprite 的 depth 同样取 `y`，遮挡自动成立。

配色保持现状（奶油地板 `#eee4cc`、墨绿墙 `#4f665d`、暖木家具），**不引入任何贴图资源**，仍全部由 graphics 绘制。

### 全国地图层

HTML 覆盖层 `src/site-map.ts`（SVG + 现有面板样式），不是 Phaser 场景——它静态、只在开场出现一次、需要点击与响应式。

```ts
// shared/sites.ts
SITES = [
  { id: 'hangzhou', name: '杭州总部', x: 62, y: 48, open: true },
  { id: 'beijing',  name: '北京',     x: 55, y: 22, open: false },
  { id: 'shenzhen', name: '深圳',     x: 58, y: 78, open: false },
]
```

只有 `open: true` 可点，其余标「筹备中」置灰。以后真有第二个办公室，加一条数据 + 一组 area 即可，不返工。

## 已知取舍

**第一期存在一处用户可见的功能回退**：办公室 1/2、休息区、茶水间今天是可以走进去的（`tests/office.test.ts` 中 `all six rooms can be entered and exited through their doors` 正在守着这条）。第一期这四间的门封为「装修中」后，它们将暂时无法进入。这是已确认的分阶段取舍，不是疏漏。对应的测试需改写为"两间开放房间可双向通过，四间封闭房间回 notice 且不换 area"，并在第二期开放时改回。

`dungeon` zone 不受本设计影响，其移动、战斗、奖励逻辑一行不动。

## 错误处理

| 情况 | 处理 |
|---|---|
| 出口反向弹跳 | 落点与触发器分离 60px + 400ms `exitCooldown` |
| 踏上封闭的门 | 回 `notice`，不换 area |
| 转场中断线重连 | 服务端状态确定（不等动画）；重连后按 snapshot 的 area 重建场景，不播动画 |
| 浏览器切后台 tween 挂起 | 权威规则兜底：本地 area ≠ snapshot area 时硬切 |
| 出生点被占用 | 候选点中挑离他人最远的 |
| `exit.to` 指向不存在的 area | AREAS 注册表自洽性由单测钉住 |

## 测试

现有 9 项测试必须保持绿。`tests/office.test.ts` 中的门口与墙体测试改写为按 area 跑。

新增：

1. 每个开放 area 的每个出口双向可通过
2. 进门后连续 30 tick 仍在目标 area（反向弹跳）
3. 封闭的门不换 area 且回 `notice`
4. 重连后保留 area 与坐标
5. 商店仅在 `area === 'storage'` 可用
6. `projectTo` 边界值不越出目标矩形
7. 随机出生点全部落在 `canStandAt` 为真的位置
8. AREAS 注册表自洽：每个 `exit.to` 存在，每个 `exit.at` 在目标 area 内且可站立

浏览器 QA 补充：两人同处会议室互相可见；一人走廊一人会议室互相不可见，但小地图上能看到对方的投影点。

## 实施顺序

每步独立可验证。

1. **数据层重构** — `shared/world/` 拆分，`canStandAt` / `moveIn` 收 area 参数。此时只有 `corridor` 一个 area，行为与现在完全一致。测试全绿即证明重构无回归。
2. **服务端 area 切换** — `area` 字段、出口触发、cooldown、`notice`、复活坐标修复。此时进门已生效，客户端硬切无动画。
3. **客户端场景与转场** — `transition` 消息、淡入淡出、场景重建、权威规则校验、小地图切换。
4. **随机出生 + 开场序列** — 全国地图层、楼层全景停留、推镜。
5. **3/4 斜视渲染** — `oblique.ts`、`area-renderer.ts`、深度排序。

斜视放最后：它是五步中最独立、返工成本最低的一步。前四步跑通时游戏已完整可玩（只是仍为平面俯视），斜视是纯渲染层替换。时间不够时砍掉它不影响任何功能。

## 不做的事

- 不做动态倾斜相机或视差（已明确选择固定角度）
- 不为房间开新的 Colyseus room
- 不引入贴图美术资源
- 第一期不开放办公室 1/2、休息区、茶水间的内部
- 不做多楼层、不做第二个地区办公室（仅预留数据结构）
