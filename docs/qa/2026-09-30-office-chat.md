# 浏览器 QA — 办公室聊天（2026-09-30）

本轮的自动化测试覆盖了能覆盖的部分（80 条全绿），**下面这些只有真人在浏览器里能验**，
原因各不相同，每节开头写了。全部未验。

跑法：`npm run dev`，开两个身份（一个正常窗口 + 一个隐身窗口）。

---

## 一、小地图上的刘正超 —— 这三条最要紧

**为什么只能手验：** 小地图原先只认 `snapshot.players`，而刘正超活在 `snapshot.enemies`
里——他的光点和他说的每一句都被整个跳过。而「他从隔壁房间点你的名」正是小地图气泡这个
功能存在的理由。

修复在 `src/map-panel.ts` 的调用点，那是 DOM 代码（`innerHTML` / `getElementById`），
node 测试到不了。单元测试钉住的是函数本身（能接受 `Enemy` 形状、会投影、不跳过、颜色可
区分），但**「调用点到底有没有把 `enemies` 传进来」只有下面这三条能抓**。

已实测确认：把调用点改回只传 `players`（即重新引入这个 bug），37 条单测照样全绿。

- [ ] 刘正超在别的房间说话时，小地图上他的位置出现截短气泡（修复前完全不显示）
- [ ] 他点名你时，小地图上那条是**薄荷绿**；点别人时是米白
- [ ] 他在小地图上有自己的光点，颜色和玩家可区分

## 二、键盘交接 —— 整轮风险最集中

**为什么只能手验：** 中文输入法的组字行为无法用自动化驱动（需要真实输入法）；
`stopPropagation` 那一半也没法在 node 里测。门控的纯函数部分已有单测钉住。

- [ ] **中文输入法**：打「你好」，组字中按 `Enter` **只确认候选词**（输入框里出现「你好」），
      再按一次 `Enter` 才发送。若第一次按 `Enter` 就把「nihao」发出去了，就是这条坏了。
- [ ] 聊天框开着时 `W`/`A`/`S`/`D` 人不动，`J` 不挥拳，**空格能正常打出**
- [ ] **开聊天前按住 `D` 不放**，按 `Enter` 开聊天，松开 `D`，发一条消息关闭聊天
      → 人不会自己往右走
- [ ] 发一条消息后，人能**立刻**走动（聊天框真的关上了，不是看起来关上了）
- [ ] 开场动画期间按 `Enter`：只跳过开场，不弹输入框
- [ ] 开场动画期间按 `1`：不发表情（和 `Enter` 一样被挡住）
- [ ] 退出登录后按 `Enter`：弹工牌对话框，不弹输入框

## 三、气泡跟着人走

**为什么只能手验：** 气泡归属是每帧从当前快照重算的，要看的是跨门那一瞬间的表现。

- [ ] A 说一句话后立刻走进大会议室：A 的气泡跟着 A 一起从 B 的画面上消失，
      不留在走廊原地
- [ ] A 在会议室说话后走回走廊：气泡出现在走廊的 A 头顶
- [ ] B 也进会议室：A 的话改到头顶显示，小地图上不再画

## 四、表情与斜杠命令

- [ ] 按 `1` 头顶出现「（挥了挥手）」，颜色比说话偏灰
- [ ] 连按 `1` `2` `3`：受 1.2 秒冷却，只有第一个出得来
- [ ] **开着聊天框打「123」**：输入框里出现 123，头顶什么都不出
- [ ] 输入框里打 `/鼓掌` 回车：出现「（鼓了鼓掌）」
- [ ] 输入框里打 `/不存在` 回车：底部出现提示，列出可用命令

## 五、名牌与转义

- [ ] 刘正超头顶的名牌读作「刘正超 · 主管」，在工位时是「刘正超 · 主管 · 在工位」
- [ ] 昵称注册成 `<b>粗</b>`：小地图上原样显示这几个字符，页面不出现粗体

## 已知缺口，不是 bug

**在房间里（大会议室 / 储物间）时，看不到别处的话。** 房间的小地图画的是那个房间自己的
平面图，上面没有任何位置能代表「别处」。所以全楼层广播在走廊上是完整的，进了房间就只
兑现一半——消息收得到，但没地方显示。

这是有意接受的取舍：硬塞一个非空间的角落浮层，会违背「小地图气泡是为了保住空间感」
这个设计决定。要补的话是另一轮的事。
